# Contoso Dentistry — Dental Office Virtual Assistant

Udacity *AI Engineer using Azure* project: a chatbot on a dentist's website. It answers patient questions and books appointment times.

**Live website:** https://yellow-sea-0b13a8003.5.azurestaticapps.net — open **Ask Denta** (bottom right).

> The site runs in the Udacity Cloud Lab. Lab sessions expire and Azure deletes their resources. If the link is down, `scripts/provision-azure.sh` and `scripts/deploy-language.js` rebuild everything (see [Rebuilding the Azure resources](#rebuilding-the-azure-resources)).

## Architecture

```
Patient ─► Static Web App (website) ──POST /api/token──► Bot App Service ──► Direct Line token
              │ Web Chat (token)                              │
              └──────────► Azure Bot Service ─────────────────┘ /api/messages
                                                              ├─► Custom Question Answering (FAQs)      ─ Language resource, West Europe
                                                              ├─► Conversational Language Understanding ─ Language resource, East US
                                                              └─► Dentist Scheduler API (App Service)
```

For every message the bot checks, in order:
1. conversation controls;
2. a tapped "Book 10am" button, or a short time reply while it is waiting for one;
3. CLU and the knowledge base, called in parallel. A scheduling intent at confidence ≥ 0.6 goes to the scheduler; otherwise a knowledge base answer at ≥ 0.5 is sent; otherwise the bot replies with a fallback.

Shared vocabulary is in [GLOSSARY.md](GLOSSARY.md).

## Changes from the course instructions

| Course says | This project does | Why |
|---|---|---|
| QnA Maker and LUIS | Azure AI Language: **Custom Question Answering** and **CLU** | QnA Maker was retired on 2025-03-31 and LUIS around 2025-10-01; see [ADR 0001](docs/adr/0001-azure-ai-language-replaces-qna-maker-and-luis.md) |
| Bot identity: App ID + password (multi-tenant) | **Single Tenant** app registration with a service principal | Azure no longer creates multi-tenant bots |
| Paste the Web Chat iframe embed code into the page | The site asks the bot's `/api/token` for a short-lived Direct Line token | The embed code puts the channel secret in public HTML |
| Create resources in the portal | `scripts/provision-azure.sh` (Azure CLI), with the GitHub workflows generated by Azure | Lab sessions expire, so the setup must be repeatable |
| CLU on the same Language resource | CLU on a second Language resource in East US | Deploying the CLU model failed with internal errors on the West Europe resource |

The starter's Dentist Scheduler is treated as an untouched third-party API. Its `POST /schedule` returns an empty body, so the bot's client accepts that.

## Running locally

```bash
cd starter/ContosoDentistryChatBot
cp .env.example .env    # or let scripts/provision-azure.sh write it
npm install
npm start               # http://localhost:3978/api/messages in the Bot Framework Emulator
```

Leave the four `MicrosoftApp*` values empty so the Emulator can connect without authentication.

## Tests

```bash
cd starter/ContosoDentistryChatBot && npm run test:coverage   # 94 tests, ~99% line coverage
cd tests/website && npm install && npx playwright test         # website smoke tests (uses installed Chrome)
node scripts/smoke-conversation.js <site-url> <bot-app-url>    # live end-to-end check through Direct Line
```

## Rebuilding the Azure resources

```bash
az login
ACCEPT_RAI_TERMS=yes RG=<lab resource group> scripts/provision-azure.sh
node scripts/deploy-language.js
```

Then:
1. Run `az webapp deployment github-actions add` for each App Service, or use the Deployment Center.
2. Create the Static Web App.
3. Update `AllowedOrigins` on the bot app and the token URL in `starter/ContosoDentistryWebsite/assets/chat-config.js`.

*Contoso Dentistry is fictional; its address, staff and reviews are invented for this project.*
